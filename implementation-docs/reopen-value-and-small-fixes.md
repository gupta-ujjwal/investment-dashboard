# Reopen-value feature + 3 small independent fixes

> Implemented via `/brainstorm` → `/develop` on 2026-09-06.

## What

Fourteen commits on `reopen-value-and-small-fixes` (branched from `origin/main`) covering two things in one PR, per an explicit user scoping decision to bundle a small independent-fixes group with the reopen-value feature:

1. **Reopen-value** — the "since your last import" delta and a 4-item action rail on the homepage (`/overview`, titled "Today"), the never-shipped half of `implementation-docs/dashboard-ux-redesign.md`'s PR-2. Required first fixing a real data-model gap: `recordSnapshot` wasn't actually called from most of the places its own docstring claimed.
2. **Three small, independent fixes** from the PM-review roadmap's "Next" bucket: Settings missing from the mobile nav, `exceljs` bloating the main JS chunk, and a missing focus trap + an always-green P&L chart.

No `DB_VERSION` bump — `Settings.lastSeenAt` is an optional scalar on the settings singleton, same precedent as every prior Phase-3/4 field. No new network egress, no new IndexedDB store.

Touches: `src/App.tsx`, `src/storage/{history,settings,backup}.ts`, `src/lib/restoreBackup.ts`, new `src/lib/sinceLastVisit.ts` + `src/lib/actionRail.ts` (+ tests), new `src/components/{ActionRail,ActionCard}.tsx`, `src/routes/{OverviewRoute,AppShell,DataBackupSection}.tsx`, `src/featureFlags.ts`, `src/parsers/{vested,groww}.ts`, `src/components/formModal.tsx`, `src/components/charts/PnlOverTime.tsx`.

## Why

**The snapshot write-model gap was larger than `history.ts`'s own docstring admitted.** It claimed `recordSnapshot` fires on "import commit, FX refresh, or an asset add/edit/delete." Verified via `grep -rn "recordSnapshot\|snapshotAfterNetWorthChange" src/`: the helper was wired into asset add/edit/delete, but not into any of the four holding-mutation intents (add/update/delete/setStatus), nor into either FX intent (refresh/manual). Trend charts and the reopen-value delta both read from `historySnapshots`, so this had to be fixed before the delta could be honest.

**The existing design doc was still accurate and worth reusing wholesale.** `dashboard-ux-redesign.md`'s PR-2 fully specs the delta + action rail (its commits 1-4); every cited function (`riskAllocation`, `emergencyFundStatus`, `portfolioTotals().unstamped`, `concentration`) matched current code exactly despite the doc predating PR #59. Current `OverviewRoute` also turned out closer to the doc's target shape than the doc itself describes — the nav already said "Today," `NetWorthSection` was already a compact 3-tile hero, not a 12-tile wall — narrowing the actual work to: insert the delta + rail, fix one stale title string. Plan's rebalance math and milestones/streaks (PR-2 commits 5-6) were explicitly deferred by the user.

**No backup/restore coverage existed for `historySnapshots`.** `storage/backup.ts` covered 5 of 6 IndexedDB stores (`grep -n "HISTORY_STORE" src/storage/backup.ts` returned zero matches before this change). Since this plan widens exactly the call sites that write to that store, a bad snapshot write would have been a one-way ratchet with no recovery path — closing this gap became part of the plan.

**Approach.** One approach considered (see `git log` for the full commit-by-commit history) — the reopen-value design was already reviewed once (the source doc), and the three small fixes each had one direct, already-diagnosed fix with no competing architecture to weigh. A plan-review pass (a 4-Shapes/Nature-Domain-Theory-Implementation lens plus a reliability-tenets filter, both run as fresh-context sub-agents against only the frame + approach, not this reasoning) converged on: split the original 10-commit plan into 14 for per-commit revert isolation (6 snapshot call sites → 2 commits by trigger class; delta/rail/small-fixes kept separate); wrap the delta in `ChartErrorBoundary` like the rail already was; require an explicit 12-test undefined-input matrix for the rule engine (2 tests × 6 rules) as the only available detection mechanism in a telemetry-free app; and add the backup-extension commit. Every finding from both reviews was folded in; one was explicitly deferred — bundling the 3 unrelated small fixes onto this branch, which was the user's own explicit choice going into the brainstorm, mitigated by one-commit-per-fix revert granularity (the same pattern PR #59 already proved).

**Pre-mortem.** Most likely failure: an action-rail rule fires with a wrong severity/threshold on a real portfolio shape the 12-test matrix didn't anticipate. Low blast radius — `FEATURE_ACTION_RAIL` ships `false`, so this surfaces during the maintainer's own pre-flip Playwright pass, never in front of a live user. Rollback: per-commit `git revert` → redeploy via `deploy.yml`; the rail's own rollback is a zero-*code-change* flag flip (still needs a commit + redeploy — flags are compile-time per `dsl.md` R9, not a runtime toggle). Detection: no telemetry (hard constraint) — the test suite plus a Playwright evidence pass against a seeded portfolio before flipping the flag.

## How

Implemented in dependency order — snapshot fixes and the backup extension first (everything else reads from that repaired data), then pure logic, then components, then wiring, then the three independent small fixes:

- **`fix(history)` ×2** — `snapshotAfterNetWorthChange` added to the 4 holding-mutation intents (`add`/`update`/`delete`/`setStatus`) in one commit, and to the 2 FX-action intents (`refresh`/`manual`) in a second — split by trigger class per the reliability review, so a regression in one doesn't force reverting the other. `history.ts`'s docstring corrected to name every actual trigger.
- **`feat(backup)`** — `exportBackup`/`restoreAll`/`BackupManifest`/`ParsedBackup` extended to cover `historySnapshots` (the 6th store), same clear-then-add-in-one-tx pattern as the other 5. `restoreBackup.ts` gained `validateHistoryRecord` (date regex, finite `capturedAt`, currency-set membership, reused `validateHolding`/`validateAsset`); `DataBackupSection`'s restore-preview grid gained a 5th "History snapshots" stat.
- **`feat(lib)`** — `sinceLastVisit.ts`'s `changeSinceLastImport`: a pure fold comparing the two most recent `historySnapshots` records. Deliberately import-anchored, not visit-anchored — comparing against "whenever you last opened the app" would show `▲ ₹0` on every visit that isn't immediately post-snapshot. Refuses to compute a delta (returns `undefined`, never a fabricated number) across a base-currency mismatch or when either day has an unpriced position — R1. 9 tests.
- **`feat(settings)`** — `Settings.lastSeenAt?: number`, optional scalar, no `DB_VERSION` bump. Feeds `sinceLastVisit.ts`'s `importsSinceLastSeen` count only, never the delta itself.
- **`feat(lib)`** — `actionRail.ts`'s `buildActionRail`: a pure fold implementing 6 rules (risk-drift, emergency-gap, stale-prices, unstamped-fx, missing-month, concentration), each partial-aware per R1 — an undefined input means "not evaluable," never "value is zero." Capped at 4 items, ordered crit → warn → info then by magnitude. 15 tests (12-test undefined-input matrix + cap/ordering/empty).
- **`feat(components)`** — `ActionRail.tsx` + `ActionCard.tsx`: three states (cold-start / all-clear / populated), wrapped in the existing `ChartErrorBoundary` bulkhead. Cards use the `sev-crit`/`sev-warn`/`sev-info` CSS tokens that shipped with PR-1 but had no consumer until now. Gated behind new `FEATURE_ACTION_RAIL` (default `false`) — same canary-gate precedent as `FEATURE_ANALYTICS_DEPTH`/`FEATURE_SECTOR_DONUT`/`FEATURE_BENCHMARK_OVERLAY`: merge dark, capture Playwright evidence, flip `true` in a one-line follow-up.
- **`feat(overview)` ×2** — the delta wired into `NetWorthSection`'s hero (always compares the two most recent snapshots regardless of `FEATURE_HISTORY`, which only gates the trend charts below), and `ActionRail` inserted immediately after, behind `FEATURE_ACTION_RAIL`.
- **`fix(overview)`** — `PageHead` title `"Overview"` → `"Today"` (both the populated and empty states) plus the first-run carousel copy — the nav already said "Today"; only the page itself hadn't caught up. Route path and component name unchanged.
- **`fix(nav)`** — the mobile top bar hardcoded a single Import link even though `AppShell.tsx`'s `utilityTabs` array already listed both Import and Settings (used correctly by the desktop sidebar). Now maps over `utilityTabs`, so the two surfaces can't drift again.
- **`fix(parsers)`** — `exceljs`'s static top-level import in both `vested.ts` and `groww.ts` became a dynamic `import('exceljs')` inside each already-`async` parse function — zero call-site changes. Confirmed via `npm run build`: `exceljs` now renders as its own `exceljs.min-*.js` chunk (930KB / 256KB gzip), no longer riding along in the main chunk on every first paint.
- **`fix(a11y)`** — `ModalShell`'s docstring promised "focus trap affordances" it never implemented. Added Tab/Shift+Tab wrap-around scoped to the panel's focusable elements, plus focus-restore to whatever triggered the dialog once it unmounts — centralized here (not duplicated into `AssetForm`/`HoldingForm`, which already each have their own autofocus-on-open and Escape-to-close effects) per the file's own stated purpose.
- **`fix(charts)`** — `PnlOverTime`'s Area stroke/gradient/dot were hardcoded to jade regardless of sign; a portfolio at a loss still rendered a green chart. Now colored by the latest point's sign, mirroring the same file's `Tip` tooltip, which already did this correctly.

**Review loop.** `/deep-review` ran once as an autonomous fresh-context sub-agent per the plan's Step 7.5. Result: **Block: 0, Request changes: 1, Follow-up: 2, Nit: 3** — no auto-fix triggered (only Block-tier is acted on autonomously). Logged here rather than silently fixed, since it's a real product decision, not a defect:

- **Request changes** — `Settings.lastSeenAt` is added, threaded into `changeSinceLastImport`, and unit-tested, but nothing in `src/` ever writes it, and its only consumer (`importsSinceLastSeen`) is never rendered anywhere. The field ships inert. This was a deliberate, narrower cut (the approved scope was "delta + rail + rename," not "wire up a visit-tracking write site") but is flagged explicitly rather than left to look accidental. **Follow-up**: pick a write site (e.g. stamp on Today-page mount, or on settings save) and a UI consumer, or drop the field until one exists.
- **Follow-up** — this branch ships several user-visible UI changes outside the plan's own pre-mortem story (the Today rename, mobile Settings nav, the live delta line, the modal focus trap, the sign-aware P&L chart). Per `.claude/rules/frontend-design.md`, Playwright verification is expected before the draft PR goes ready-for-review — that's the engineer's next step, not part of `/develop`.
- **Nit** (not acted on, low-impact) — `OverviewRoute.tsx`'s `now={Date.now()}` is computed inline, which defeats `ActionRail`'s internal `useMemo`; the action-rail rule engine's severity tie-break compares magnitudes across incomparable units (days vs. count) when two same-severity rules fire together.
