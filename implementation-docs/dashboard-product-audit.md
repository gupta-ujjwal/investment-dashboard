# Plan: Investment Dashboard — Product Audit & Prioritized Roadmap

> Generated by `/brainstorm` on 2026-06-27. Working notes + screenshots at `notes/dashboard-product-audit/`
> and `implementation-docs/evidence-dashboard-product-audit/`. Deliverable type: **full prioritized audit** (PM lens) — no single build
> slice locked; lead theme **Trust & consistency**, extended (per user) with connective tissue + new features.

## How this was produced
Drove the live app via Playwright with seeded two-market data — 20 US (Vested) + 29 India (Groww) imported
holdings + 1 manual savings asset = ₹36.2L net worth — walked every route at desktop (1280px) and mobile
(390px), and cross-checked findings against the source (`src/routes/*`, `src/lib/*`, `src/storage/*`). FX
auto-stamped at import (1 USD = ₹94.40). No app console errors (only a favicon 404 + benign react-router
warnings).

## Executive summary
The dashboard is, surface for surface, well-built: a genuinely strong editorial-dark design system that holds
up on mobile, a rich Equity analytics page (HHI concentration, top-5 weight, single-stock risk, sector/
allocation/movers), and a clean two-broker import wizard. The problem is not craft — it's **trust and
connection**. Several headline numbers are wrong or misleading, and the tabs are well-built *silos* that don't
share the data they each already hold. For a personal-finance product, both are existential: a tool people
won't trust the numbers of, or that makes them re-type the same fact in three places, doesn't get used.

Three movements, in priority order:
1. **Make the numbers trustworthy** (lead theme) — fix the surfaces that currently disagree or mislead.
2. **Connect the tabs into a flywheel** — most of the wiring already exists half-built; connecting it is
   higher ROI than new surface area.
3. **Extend toward "all finance"** — liabilities/true net worth, price refresh, dividends, tax-aware gains,
   insights — once the base is trustworthy and connected.

## What's strong (preserve — do not "improve" these into inconsistency)
- **Design language.** Editorial-dark (ink/bone/amber, serif numerics, mono labels) is consistent across all
  7 tabs and at 390px. A real asset; keep it as the system of record for any new surface.
- **Equity analytics page.** The best surface in the app — KPIs + risk metrics + sector/allocation/movers +
  searchable, filterable, sortable holdings with a desktop-table→mobile-card switch.
- **Import wizard + data model.** Clean 5-step flow; honest partial-value discipline (`undefined`, not
  sentinel 0); atomic commit; FX stamped at write not render. The `goals.ts` projection even names its
  conservative model honestly.

## Findings — severity-ranked

### P0 · Trust & consistency (numbers that are wrong, misleading, or leak)
1. **Investments tab mislabels asset class.** Overview's class breakdown and per-holding chips show MF/ETF/
   InvIT, but `InvestmentsRoute` collapses all 49 holdings into two rows both labeled **"Equity"**. Two tabs
   disagree about what you own. (`InvestmentsRoute.tsx`)
2. **Planning is blind to ~86% of the portfolio.** `PlanningRoute`'s loader fetches **only manual assets**
   (`App.tsx:103`), never holdings; `riskBand`/`emergencyFund` exist *only* on `ManualAsset`
   (`storage/assets.ts:52-53`), and imported holdings have no risk-band field or tagging UI. So risk-mix +
   bulk-invest + emergency-fund see the ₹5L manual asset and ignore the ₹31L imported book. Structural, not
   cosmetic. → fix via a single, tested `assetClass→riskBand` derivation (equity=High, ETF/MF=Moderate,
   gold/FD/savings/cash=Safe), user-overridable, feeding the whole portfolio into Planning.
3. **"STALE" means "imported in an older batch," not "old price."** `isStale = importedAt < newest import`
   (`holdingsView.ts`): importing India after US flags every US holding STALE though nothing about its price
   changed. Misleading freshness signal. → redefine staleness around price as-of, or scope it per import batch.
4. **Privacy / opt-in-egress constraint violation.** CLAUDE.md mandates a master "External APIs: on/off"
   switch + per-feature toggles + first-run disclosure. None exist, and FX is fetched from Frankfurter
   **automatically at import** with no consent (watched it stamp 1 USD=₹94.40). This is egress-by-default —
   a hard-constraint breach, and a trust/credibility issue for a "stays on your device" product.
5. **"Net worth" over-claims.** Overview headline ("Your whole net worth") is **gross assets** — no
   liabilities, so it can never be reduced by a loan. Until liabilities exist, relabel honestly
   ("Total assets" / "Net worth · assets").

### P0.5 · Cross-cutting trust gate (from review)
**Trust is an invariant, not a one-time wave.** Every later change that touches a number (liabilities math,
FX staleness, history series) re-opens the trust surface. Apply a standing acceptance gate to W2–W4: *no
change ships if it makes a displayed number wrong, and any data-mutating change is flagged + revertable*
(see Release rules).

### P1 · Connective tissue (the flywheel — the highest-leverage product work)
The thesis: **well-built tools that don't talk to each other.** The loop a finance product wins on is
record → reconcile → project, and the data is already there — it just isn't wired.
6. **Budget → Planning.** Budget computes monthly expenses (`lib/budget.ts`), yet Planning's emergency
   monthly need is **re-typed in Settings** (`emergencyMonthlyNeed`). Derive it from Budget's avg expenses
   (override allowed). Kills double entry.
7. **Budget → Goals.** Goal projection (`goals.ts`, on Overview) takes its monthly contribution from Settings
   (typed). Derive from Budget's actual savings/invested.
8. **Budget → Overview.** Budget's savings-rate / spent% / runway never appears on Overview (the
   `dashboardLoader` doesn't even fetch budget months, `App.tsx:83-88`). Add a savings-rate + "months of
   runway" card. (Depends only on already-persisted budget data.)
9. **Holdings → Budget.** "Invested this month" is typed by hand though holdings know contribution deltas —
   pre-fill it.
10. **Overview as the hub.** Make each card deep-link to its tab (net worth→Investments, P&L→Equity,
    asset-class→Equity filtered, goal→Planning, emergency→Planning).
11. **Kill the Settings round-trips.** Planning shows "set X in Settings" 3× — let users edit targets / needs
    inline on the Planning page.

### P2 · New features (senior PF-PM, Phase-1-appropriate, edge-only, India+US)
12. **Liabilities / debt → true net worth** (loans, cards, EMIs). Foundational for an honest "net worth."
13. **Net-worth trend & milestones** — surface the history snapshots that already exist (MoM/YoY delta,
    sparkline, "crossed ₹50L"). Seed a **baseline snapshot at import** so day-1 shows a point (also fixes
    cold-start).
14. **Price refresh (opt-in, user key, behind the consent layer) + "paste latest price" quick path** —
    prices are frozen broker-export snapshots; P&L decays with no update path short of a full re-import.
15. **Tax-aware gains** — India LTCG/STCG (1yr threshold, ₹1.25L LTCG exemption), US ST/LT. Strong India
    differentiator. *Data-gated on acquisition dates — verify broker exports carry them before committing.*
16. **Dividend / passive-income tracking** (InvITs, dividend stocks; yield-on-cost). Manual entry acceptable.
17. **Rebalancing drift** — extend existing `allocationTargets` + `bulkAllocation` to show drift and
    sell/buy nudges.
18. **XIRR / annualized return** — naive P&L% today; time-weighted is the PF-credible metric. Date-gated.
19. **Multi-currency view + FX attribution** — net worth in INR *and* USD; "how much of my gain is FX vs
    underlying." Core to the two-markets constraint.
20. **Multiple named goals** (house, retirement, education) with target/date, earmarking tagged assets.
21. **Local insights engine** — pure folds over the *connected* data ("NVDA is 12% of book", "emergency fund
    covers 2.1 months", "savings rate fell to 8%", "12% over High-risk target"). No server.
22. **Expense / transaction CSV import** — reuse the on-device broker-parser architecture for bank/card
    statements; turns manual monthly totals into real budgeting.
23. **Demo / sample-data mode + onboarding** — explore before importing; fixes cold-start first impression;
    pairs with the mandated privacy-consent first-run banner.

### P3 · Polish
24. **Donut redundancy** — Allocation(Market) and Currency-exposure show identical data in a 2-market app
    (both 58/42). Merge, or repoint one to sector/asset-class.
25. **Sector coverage** — Sector donut is ~48% "Unknown"; `sectors.json` doesn't cover Indian tickers/ETFs/
    InvITs. Expand mapping or label honestly.
26. **Mobile nav discoverability** — 7-item nav at 390px is `overflow-x:auto` (scrollWidth 553 > client 325);
    Import + Settings sit off-screen with no hamburger / scroll affordance. (`AppShell.tsx`) *UX track, not the
    numbers-trust wave.*
27. **"Add asset" defaults to Crypto** — pick a neutral default; consider units/qty for gold/crypto.
28. **Backup excludes history snapshots**; **no "wipe all data / reset"** action (only overwrite-restore).
29. **Naming** — "Equity" tab actually holds all 49 incl. MF/ETF/InvIT; "Investments" KPI "Equity: 2" is
    ambiguous; Settings copy "goal projection on Analytics" is stale (it's on Overview).

## The flywheel (target architecture for connection)
```
                 ┌─────────── Budget (income / expenses / savings rate) ───────────┐
                 │  avg expenses → emergency need   savings → goal contribution     │
                 ▼                                                                   ▼
   Holdings + Manual assets ──(value)──►  Overview = NET WORTH = assets − liabilities  ──► Goals (years-to-goal)
                 │                                ▲                       │
       assetClass→riskBand (derived)             │ deep-links            │ months-of-runway = liquid ÷ expenses
                 ▼                                │                       ▼
            Planning (risk mix, rebalance, emergency cover) ◄── sees WHOLE portfolio, not 14%
                 │
                 └──────────► Local insights engine (pure folds over the connected data)
```
Today every arrow above is missing. Liabilities (dashed box) doesn't exist yet.

## Recommended sequencing (Approach 1, revised by the review)
Slice by **reversibility**, not just theme: within every wave, "mutates user data / egress" items are
flagged + individually revertable + gated; "pure UI" items ship freely.

- **W1a — Correctness (pure render/logic, no data mutation, ship freely):** Investments asset-class roll-up
  (#1); `assetClass→riskBand` derivation so Planning sees the whole portfolio (#2, one tested mapping module
  + visible override); `isStale` redefinition (#3); relabel "Net worth"→assets-honest (#5); FX-staleness shown
  as a trust signal.
- **W1b — Consent + history write-model (data/egress, flagged + gated):** the consent gate that wraps the
  *existing* FX egress (master off by default; **upgrade path leaves egress OFF for existing users — no silent
  opt-in**; CI test asserts no network call before consent) behind `FEATURE_CONSENT`; baseline-snapshot-at-
  import behind `FEATURE_BASELINE_SNAPSHOT` (idempotent; one row per YYYY-MM-DD; never overwrites prior days).
- **W2 — Connective tissue:** Budget→emergency-need, Budget→goal-contribution, savings-rate + runway on
  Overview, Overview hub deep-links, inline Planning config, pre-filled "invested this month". (Candidate:
  a lightweight reconcile / "as-of" affordance — the user is the recon authority in a backend-less app.)
- **W3 — New features:** liabilities + true net worth (own wave; backup-export-before-migrate + export→wipe→
  restore round-trip test as the ship gate); net-worth trend/milestones; price refresh (opt-in, first egress
  feature — justifies the W1b consent layer); dividends; rebalancing drift; multi-currency; named goals;
  insights.
- **UX track (parallel, anytime):** mobile nav (#26), donut dedupe (#24), sector coverage (#25), Add-asset
  default (#27), copy/naming (#29), backup-includes-history + wipe-all (#28).

## Release rules (from reliability review)
- Each data-mutating item rides its own `featureFlags.ts` flag with a documented on-device revert (flip flag +
  redeploy static bundle; user restores pre-change backup for migrated data).
- IndexedDB migrations (W3 liabilities) never share a release with cosmetic changes; ship gate = backup +
  round-trip test.
- Centralize any derived value (e.g. `assetClass→riskBand`) in one unit-tested module — it fans out to
  Planning/Overview/insights, so a wrong mapping is silently wrong everywhere at once.

## 4 Shapes (from the develop-perspective review)
- **Nature**: a trust-bearing instrument — one wrong reading poisons every correct one beside it; trust erodes
  continuously, so it's an invariant, not a wave.
- **Domain**: load-bearing nouns are net worth / cash flow / position / plan; record→reconcile→project; the
  user is the reconciliation authority (no backend), and the app gives them no way to confirm a total.
- **Theory**: fold over an event log into derived views; "derive don't store" (risk band) is the clean move;
  trend/milestones need a monotonic history series built *before* the views that read it.
- **Implementation**: derive-with-override is the right smallest spike; but the consent layer is medium-large
  and shouldn't share a wave with a one-line fix; FX is on the trust critical path.
- **Tensions**: trust-as-wave vs trust-as-invariant; consent-valve-before-its-water; tissue and the
  Planning trust-fix are the same work.

## Picked Reliability Tenets (from the reliability-tenets review)
- **Tenet 2 (critical path simple)**: isolate data-mutating changes (consent, snapshot seed, migration) from
  cosmetic ones — never share a release boundary.
- **Tenet 3 (blast radius)**: the derived risk-band fans out to many surfaces — centralize + unit-test the
  mapping so a bad band can't propagate unaudited.
- **Tenet 6 (staggered rollout + rollback)**: per-item flags; consent defaults OFF and stays OFF on upgrade;
  on-device rollback is flag-flip + user backup restore; migration gated by a round-trip test.

## Pre-mortem
- **Most likely failure**: W1b's baseline-snapshot is implemented as a naive "add snapshot on commit" → a
  same-day re-import overwrites/double-writes the YYYY-MM-DD `historySnapshots` row, corrupting the series the
  trend charts later read; and/or the consent layer is added while the *existing* FX-at-import egress keeps
  firing, so the app still calls Frankfurter before any opt-in.
- **Rollback**: per-item flags in `featureFlags.ts` (`FEATURE_CONSENT`, `FEATURE_BASELINE_SNAPSHOT`); flip off
  + redeploy the static bundle. W1 adds no schema, so nothing to reverse. The irreversible W3 liabilities
  migration is gated separately (backup-before-migrate + export→wipe→restore→assert-unchanged); user-level
  revert = restore pre-migration backup.
- **Detection + responder**: no runtime telemetry is allowed, so detection is build-time + manual — (1) a
  Vitest assertion that no network call fires on import/load while consent is OFF; (2) a unit test that a
  same-day re-import leaves exactly one snapshot row and preserves prior days; (3) the existing Playwright
  evidence pass re-run on the seeded two-market fixture. Responder = the single owner.
