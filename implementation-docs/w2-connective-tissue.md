## Frame
- **Kind**: feature (connect existing tabs; pure folds + loader plumbing + UI, no schema change).
- **Files/modules likely touched**: `src/lib/budget.ts` (new `monthlyAverages`), a small precedence helper
  (`effectiveEmergencyNeed`/`effectiveContribution` — in `lib/planning.ts`/`lib/goals.ts` or a new
  `lib/cashflow.ts`), a `liquidAssets` fold (`lib/netWorth.ts` or `lib/cashflow.ts`), `src/App.tsx`
  (Overview + `planningLoader` fetch budget months; reuse `settingsAction`), `src/routes/OverviewRoute.tsx`
  (Cash-flow card + deep-links), `src/routes/PlanningRoute.tsx` (inline config + budget-derived need),
  `src/routes/BudgetRoute.tsx` (#4 hint), plus tests.
- **Slice(s) / component(s)**: Analytics Engine (`budget.ts`, `planning.ts`, `goals.ts`, `netWorth.ts`),
  Routing (`App.tsx` loaders/action), route UI (Overview/Planning/Budget).
- **External surface affected**: none. No IndexedDB schema change; `DB_VERSION` stays 5. #6 reuses the
  existing `settingsAction` write path (verified to merge).
- **Out of scope**: liabilities / true net worth (W3); transaction/CSV import; a real per-buy "invested"
  source (#4 stays a hint); price refresh; net-worth relabel; an "essential expenses" classification.

## Research summary
- Budget folds `summarizeMonth`/`summarizeAll` exist; **no per-month-average** helper (`lib/budget.ts`) —
  need `monthlyAverages`. Budget is single base-currency (`budget.ts:3-9`).
- Overview `dashboardLoader` = `{holdings, settings, history, assets}`, **no budget**
  (`OverviewRoute.tsx:30-44`). Emergency + goal cards already call `emergencyFundStatus(assets,
  settings.emergencyMonthlyNeed, settings.emergencyMonths)` (`:63`) and `projectGoal(current,
  settings.goalCorpus, settings.monthlyContribution)` (`:59`). Cards not deep-linked (`Link` already imported).
- `planningLoader` (post-#2) = holdings+assets+settings (`App.tsx:104`); `budgetLoader` = budget months.
- `settingsAction`/`readSettingsFromForm` (`App.tsx:165-186`) **merges** — spreads `...current` and keeps
  each field when its form input is absent (`readTarget` → `'keep'`). So an inline partial `intent=save`
  preserves every omitted field (and any future consent/keys via the spread). This makes #6's reuse safe.
- Settings optional fields: `emergencyMonthlyNeed?`, `emergencyMonths?`, `goalCorpus?`, `monthlyContribution?`,
  `allocationTargets?` (`storage/settings.ts:20-30`).
- History (`storage/history.ts:17-32`) = one record per net-worth-moving day (import/FX/asset-edit); **budget
  edits do not snapshot** (`history.ts:64`), so snapshots are sparse — the reason #4 can only be a best-effort
  month-over-month delta, shown when two snapshots cleanly bracket a month, else omitted.
- Manual-asset classes include `cash`/`savings`/`fd` (`storage/assets.ts:12-21`) — the runway "liquid" set;
  values via `currentValueBase` (base-currency, FX-stamped) so no cross-currency ratio.

## Approaches considered

### Approach 1: Three cohesive sub-PRs, Settings-as-override, honest #4 hint (RECOMMENDED)
- **PR-A — Budget feeds the flywheel (#1/#2/#3):** `monthlyAverages(months)` (returns `undefined` under 2
  months); a tested `effectiveEmergencyNeed(settings, derived)` / `effectiveContribution(settings, derived)`
  precedence helper (Settings `undefined` = unset→derived, explicit `0` = honored override); a `liquidAssets`
  fold (cash+savings+FD manual assets only, **not** equity); an Overview **Cash flow** card (hero = savings
  rate + avg income/expenses/net; secondary = "total liquidity" months-of-runway); feed the derived
  need/contribution into the existing emergency + goal cards on Overview *and* Planning, each with a
  "from Settings"/"budget-derived" provenance label. Add budget months to the Overview loader + `planningLoader`.
- **PR-B — inline config + deep-links (#5/#6):** wrap Overview Net-worth/Emergency/Goal sections in `Link`s;
  replace Planning's 3× "set in Settings" with inline `fetcher.Form` fields posting `intent=save` to the
  (merging) `settingsAction`. Pure UI + reuse.
- **PR-C — invested hint (#4):** a read-only **month-over-month holdings cost-basis delta** beside Budget's
  *invested this month*, shown only when two history snapshots cleanly bracket the month; otherwise omitted.
  Clearly labeled and separated from the input; never a lifetime total, never an auto-fill.
- **Risks**: runway/emergency duplication (resolved — savings-rate hero + distinct liquid set/framing);
  precedence bugs fanning to three surfaces (one tested helper); zero/sparse-month instability (≥2-month
  guard + `undefined` identity).
- **Complexity**: PR-A medium, PR-B small, PR-C small.
- **Tradeoffs**: three focused reviews; the data-limited #4 is isolated so it can't hold up the clean links;
  each PR reverts independently. Primitives: *extend* (folds/loaders/settingsAction), *now-vs-later* (#4 hint
  now, real contributions source deferred to W3), *derive-don't-force* (Settings override).

### Approach 2: One PR for all six links
- Single branch. Less process overhead, but couples pure-UI (#5) with data-limited (#4) and new folds, one
  #4 problem blocks the wave, harder to revert one link. Fallback only if a single PR is explicitly wanted.

### Approach 3 (rejected): build a real per-month "invested" source for #4
- A dated-transactions store so #4 is a true computed figure. Rejected: new schema + import surface = W3-scale;
  broker exports lack buy dates so the source would itself be manual (reproducing the double-entry #4 removes).

## 4 Shapes (from the develop-perspective review sub-agent)
- **Nature**: a watershed — income in, pools as liquid savings, drains as expenses; runway is reservoir depth
  ÷ outflow. "Derive-with-override" = a default channel with a manual sluice gate.
- **Domain**: numerator matters — equity isn't emergency liquidity; sparse months make averages unstable;
  emergency need is conventionally *essential* (not all-in) spend; currency must not silently mix.
- **Theory**: `effectiveX = settingsX ?? derivedX` is the right abstraction, but it's **tri-state**
  (unset / explicit-0 / derived-unavailable) — both "unset" sentinels must be `undefined`, never `0`.
- **Implementation**: three-PR slice is well-cut; cold-start (never-opened-Budget) is the highest-friction,
  most-likely-NaN path; #4's lifetime cost basis is a category error beside a monthly field.
- **Tensions**: runway vs emergency-coverage as near-duplicate gauges (the central decision); #4 honest
  framing vs wrong quantity.

## Picked Reliability Tenets (from the reliability-tenets review sub-agent)
- **Tenet 2 (critical path simple)**: the only state-mutating path is #6 reusing `settingsAction` — keep its
  write contract minimal; derivations are pure reads.
- **Tenet 3 (blast radius)**: a wrong precedence rule fans to three surfaces (one tested helper); a
  replace-write `settingsAction` would clobber consent/keys on a partial save (verified: it merges).
- **Tenet 1 (graceful degradation)**: every fold returns `undefined` on zero denominator / absent data; cards
  render defined empty states, never `NaN`/`Infinity`.
- **Tenet 4 (detection, no telemetry)**: build-time unit tests on degenerate inputs + a visible provenance
  label so the user is the anomaly detector.

## Pre-mortem
- **Most likely failure**: a single logged Budget month slips past the ≥2-month guard → runway/emergency-need/
  goal-contribution all render a confident but meaningless number on three surfaces at once; and/or the #4
  delta is computed across snapshots that don't cleanly bracket the month, mislabeling a multi-month sum as
  "this month."
- **Rollback**: per-PR `git revert`; no schema change / migration (all links read existing stores; the only
  write, #6, goes through the already-merging `settingsAction`), so nothing to migrate back and user data is
  untouched. Surfaces are already feature-flag-gated.
- **Detection + responder**: build-time gates (no telemetry) — `monthlyAverages` ≥2-month test; precedence
  three-state test; cold-start empty-Budget test; `settingsAction` partial-save-preserves-field test; the UI
  provenance label; Playwright on 0/1/3 budget months. Single owner; any red gate blocks merge.
