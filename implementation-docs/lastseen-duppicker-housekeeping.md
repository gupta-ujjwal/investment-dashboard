# lastSeenAt wiring + duplicate-row picker + housekeeping

> Implemented via `/brainstorm` → `/develop` on 2026-09-07.

## What

Six commits on `lastseen-duppicker-housekeeping` (branched from `origin/main`) covering three independent items the user asked to bundle into one pass:

1. **`Settings.lastSeenAt` wiring** — closes a `/deep-review` finding from PR #61: the field was threaded through `changeSinceLastImport` and unit-tested, but never written, and `importsSinceLastSeen` was never rendered.
2. **A duplicate-row Combine/Keep-last picker** for the import wizard — extends the already-shipped dedup from PR #59 (`DiffResult.duplicates`) into a real per-group decision UI, per `DuplicateRow`'s own doc comment forward reference.
3. **Three housekeeping fixes**: a missing wizard step counter, a missing favicon, and stale post-rename button copy.

No `DB_VERSION` bump, no new store, no new network egress.

Touches: `src/routes/OverviewRoute.tsx`, `src/parsers/diff.ts` (+ tests), `src/routes/import/{PreviewStep,wizardState,CommitStep}.tsx`, `index.html`.

## Why

**Item 1.** `src/storage/settings.ts`'s `lastSeenAt?: number` and `sinceLastVisit.ts`'s `importsSinceLastSeen` computation both already existed and worked correctly — they just had no write site and no consumer. A user revisiting Today had no way to see "3 imports happened since you last looked."

**Item 2.** `diff.ts`'s `DuplicateRow` type already carried its own doc comment naming this exact feature: "kept as data... so a future per-row Combine/Keep-one picker can consume it directly without re-parsing the file." PR #59 shipped the minimal fix (keep-last + a count) specifically so this could be built without re-deriving anything.

**Approach.** All three items extend a directly analogous existing pattern rather than inventing new architecture — item 1 reuses `saveSettings` (new call site, existing function) and mirrors the render-then-effect timing already used for autofocus in `HoldingForm`/`AssetForm`; item 2's `DuplicatesPanel` is structurally identical to the already-shipped `MissingRowsPanel` (per-row decision buttons, bulk actions, a decision map in `WizardState`, applied at commit time); item 3 is three one-line-scale fixes. A plan-review pass (a 4-Shapes lens and a reliability-tenets filter, both run as fresh-context sub-agents against only the frame + approaches, not this reasoning) sharpened item 2 concretely: pinned the combine formula as a single-pass fold over the whole lot list (a naive pairwise-chained implementation would silently produce the wrong number for 3+ duplicate lots — the reviews independently caught this); added a pre-commit preview of the computed combined values in the picker itself; confirmed via direct code citation (`diff.ts`'s per-source throw + per-source diff calls) that the reviews' cross-market `sourceSymbol`-collision concern cannot actually occur, rather than adding unneeded scoping logic; and added a guard refusing to combine a group containing any zero/negative/missing-value lot.

**`/deep-review` caught something the plan-review pass missed.** The autonomous review-and-fix loop (Step 7.5) ran twice. First pass found 2 Block findings, both fixed in `ee78798`:

1. **`combineDuplicateGroup` silently corrupted a sticky manual-override.** If a user had previously corrected a holding's `avgBuyPrice` via the inline-edit "sticky override" mechanism (`manualOverrides: ['avgBuyPrice']`), and that holding later appeared in a duplicate group, the combine math blended the user's manual correction with a discarded lot's raw broker price into a number that *still claimed the override marker* — silently overwriting a correction the user made on purpose, with no signal that it happened (`productContext/dsl.md` § R13). Reproduced directly against a fixture (a 999 manual override blended with 100/110 broker-reported lots) before fixing.
2. **The plan's own Pre-mortem claimed something false.** It said item 3 ships as 3 fully independent, individually-revertible commits — but the step-04/04 label fix landed bundled inside the `DuplicatesPanel` commit (`8561d0b`) rather than its own. Corrected here rather than rewriting git history: 3a's revert is bundled with item 2's; 3b (favicon) and 3c (copy fix) are each their own commit and independently revertible as originally planned.

Second pass came back clean: 0 Block findings, confirming both fixes hold under a fresh, unbiased read of the diff.

**Pre-mortem.** Most likely failure: a user picks "Combine" on a legitimate two-lot duplicate, the math is correct, but they don't notice the pre-commit preview and are later confused by a `quantity`/`avgBuyPrice` that doesn't match either original lot. Mitigated by the preview itself (shown before commit) and by the combined row remaining fully editable afterward via the existing holding-edit UI — the same recovery path as any other data-entry correction in this app; there is no undo-after-commit anywhere in this codebase, not a gap specific to this feature. Rollback: `git revert` per commit (see the corrected Rollback note above for item 3's actual bundling); no `DB_VERSION` change in any direction. Detection: no telemetry (hard constraint) — item 2's correctness is gated by the pre-commit preview, the single-pass-fold implementation with an independently-computed 3-way test, the zero/negative/missing-value guard, and now the manual-override guard; item 1's timing behavior needs a Playwright evidence pass (not yet captured — see Status).

## How

Implemented in dependency order — the lastSeenAt effect first (self-contained), then the combine primitives (pure, independently tested), then the UI wiring, then the three housekeeping fixes:

- **`feat(overview)`** — a `useEffect` in `OverviewRoute.tsx` stamps `saveSettings({ ...settings, lastSeenAt: Date.now() })` on Today-page mount, placed *before* the component's early return (hooks must stay unconditional) and guarded to skip the true empty state. Depends only on `[empty]`, not `settings`/`history` — fires once per mount, not on every settings write. Renders "N imports since you last looked" inline with the existing since-import delta when `importsSinceLastSeen > 0`. Failure is logged via `console.warn`, matching the sibling `recordSnapshot` best-effort pattern elsewhere in the import flow (fixed during `/deep-review`, was originally a silent `.catch(() => {})`). Known, accepted limitation: a same-session revisit clears the badge, since the watermark already advanced — this exact tradeoff (vs. stamping on navigate-away) was decided explicitly in this plan's grill loop, not an oversight.
- **`feat(parsers)`** — `groupDuplicates`/`combineDuplicateGroup`/`applyDuplicateDecisions` in `diff.ts`. `groupDuplicates` reconstructs each duplicate group's full lot list (discarded lots + the survivor `diffHoldings` already kept) from a `DiffResult`, pure and read-only. `combineDuplicateGroup` computes the quantity-weighted-average combine as a single pass over the whole lot list (never pairwise-chained partial averages — the associativity bug the plan-review caught), refusing (`undefined`) on any lot with a non-finite/non-positive `quantity`/`avgBuyPrice`, and — after the `/deep-review` fix — refusing whenever the survivor carries a sticky `manualOverrides` entry for `'quantity'` or `'avgBuyPrice'`. Every other field carries through from the survivor unchanged. Operates only on pre-stamp fields; structurally cannot run after FX stamping since `diff.inserts`/`diff.updates` never carry `avgBuyPriceBase`/`currentPriceBase` at the point `diffHoldings` produces them. 13 new tests: grouping (0/2-way/3-way), combine math (2-way, 3-way associativity guard, field passthrough, zero/negative/NaN refusal, manual-override refusal), and decision application (default/explicit keep-last, combine in both insert and update buckets, fallback-to-keep-last on a refused combine).
- **`feat(import)`** — `DuplicatesPanel` in `PreviewStep.tsx`, sibling to the existing `MissingRowsPanel`: per-group Keep-last/Combine buttons plus bulk actions, showing the computed combined quantity/avgBuyPrice inline before commit. New `WizardState.duplicateDecisions: Record<string, DuplicateDecision>` (default `'keep-last'` per key — unchanged unless the user opts in) plus 2 reducer actions mirroring the existing missing-row decision pattern. `handleCommit` applies decisions via `applyDuplicateDecisions` before FX stamping. This commit also carries the step-04/04 wizard-counter fix (landed in the same file edit; see the corrected Pre-mortem/Rollback note above for why this makes item 3a not independently revertible).
- **`fix(pwa)`** — an inline-SVG favicon (`data:image/svg+xml` URI in `index.html`) reusing the exact brand mark `AppShell.tsx` already renders (rotated square, `tick-400`/`#5b6ef5`) — zero new asset file, zero third-party request, matching the self-hosted-fonts precedent from earlier work on this app.
- **`fix(import)`** — `CommitStep.tsx`'s "View analytics →" → "Go to Today →"; confirmed via `grep -rn '"Overview"\|>Overview<\|View analytics' src/` that this was the only remaining stale Overview-era string, so the fix closes the earlier rename rather than introducing a new inconsistency.
- **`fix(parsers)`** — the two `/deep-review` Block fixes described above, bundled in one commit (`ee78798`): the manual-override combine guard + its test, and the lastSeenAt `console.warn`.

**Review loop.** `/deep-review` ran twice (cap 2). First pass: **Block: 2, Request changes: 2, Follow-up: 1, Nit: 1** — both Blocks fixed (above); one Request-changes (silent lastSeenAt failure) fixed in the same commit; the other Request-changes (verify combine-before-stamp ordering, already structurally enforced) confirmed correct on re-read. Second pass: **Block: 0, Request changes: 2, Follow-up: 1, Nit: 1** — clean on Blocks. The remaining Request-changes/Follow-up/Nit are logged, not auto-fixed (only Block-tier triggers autonomous action):

- **Request changes** — this plan doc was edited but not yet committed at the time of the second review pass. Resolved by this commit.
- **Request changes** — Playwright evidence for item 1's badge-timing behavior not yet captured. This is `.claude/rules/frontend-design.md`'s draft-PR-readiness gate, not part of `/develop`'s own scope — captured as part of this PR's evidence pass (see the `## Evidence` PR comment).
- **Follow-up** — `productContext/architecture.md`'s Import Pipeline section doesn't yet mention the new `DuplicatesPanel`. Doc drift, not blocking; left for a future docs pass.
- **Nit** — `OverviewRoute.tsx`'s lastSeenAt write reuses the loader's settings snapshot rather than re-fetching fresh immediately before the write (unlike `updateFxMeta`). Negligible practical risk in this single-tab, single-user app.
