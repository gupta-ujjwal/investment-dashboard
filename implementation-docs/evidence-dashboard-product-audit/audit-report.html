01

Executive summary

Surface for surface, this is well-built: a genuinely strong editorial-dark design system that holds up on mobile, a rich Equity analytics page (HHI concentration, top-5 weight, single-stock risk, sector / allocation / movers), and a clean two-broker import wizard. The problem is not craft — it is trust and connection. Several headline numbers are wrong or misleading, and the tabs are well-built silos that don't share the data they each already hold. For a personal-finance product both are existential: a tool people won't trust the numbers of, or that makes them re-type the same fact in three places, doesn't get used.

Movement 1

Make the numbers trustworthy

The lead theme. Fix the surfaces that currently disagree, mislead, or leak — before adding anything new.

Movement 2

Connect the tabs into a flywheel

Most of the wiring already exists half-built. Connecting it is higher ROI than new surface area.

Movement 3

Extend toward all finance

Liabilities, true net worth, price refresh, dividends, tax-aware gains, insights — once the base is solid.

02

What's strong — preserve

Do not "improve" these into inconsistency. They are the bar the rest of the app should meet.

Design language

Editorial-dark system

Ink / bone / amber, serif numerics, mono labels — consistent across all 7 tabs and at 390px. A real asset; the system of record for any new surface.

Analytics

The Equity page

The best surface in the app: KPIs + risk metrics + sector / allocation / movers, and a searchable, filterable, sortable table with a desktop-table → mobile-card switch.

Data model

Import & honesty

Clean 5-step wizard; partial values stay undefined, never sentinel 0; atomic commit; FX stamped at write, not render. The goal projection even names its conservative model.

03

Findings — severity ranked

Twenty-nine findings across five tiers. P0 is the lead theme: numbers that are wrong, misleading, or leak. Each carries a one-line fix direction.

P0 · Trust & consistency numbers that are wrong, misleading, or leak
1
Investments tab mislabels asset class

Overview's class breakdown and per-holding chips show MF / ETF / InvIT, but the Investments roll-up collapses all 49 holdings into two rows both labeled "Equity." Two tabs disagree about what you own.

Fix — group by real asset class; stop labeling MF/ETF/InvIT as Equity. InvestmentsRoute.tsx
2
Planning is blind to ~86% of the portfolio

The Planning loader fetches only manual assets (App.tsx:103), never holdings; riskBand / emergencyFund exist only on ManualAsset. So risk-mix, bulk-invest, and emergency-fund see the ₹5L manual asset and ignore the ₹31L imported book. Structural, not cosmetic.

Fix — one tested assetClass→riskBand derivation (equity=High, ETF/MF=Moderate, gold/FD/savings/cash=Safe), user-overridable, feeding the whole portfolio into Planning.
3
"STALE" means "older import batch," not "old price"

isStale = importedAt < newest import — importing India after US flags every US holding STALE though nothing about its price changed. A misleading freshness signal.

Fix — redefine staleness around price as-of, or scope it per import batch. holdingsView.ts
4
Privacy / opt-in-egress constraint violation

CLAUDE.md mandates a master "External APIs" switch + per-feature toggles + first-run disclosure. None exist, and FX is fetched from Frankfurter automatically at import with no consent. Egress-by-default — a hard-constraint breach and a credibility issue for a "stays on your device" product.

Fix — a consent gate that wraps today's FX egress (off by default), per-feature toggles, first-run banner.
5
"Net worth" over-claims

The Overview headline ("Your whole net worth") is gross assets — no liabilities, so it can never be reduced by a loan.

Fix — until liabilities exist, relabel honestly ("Total assets" / "Net worth · assets").
P0.5 · Cross-cutting gate from the unbiased plan review
6
Trust is an invariant, not a one-time wave

Every later change that touches a number (liabilities math, FX staleness, the history series) re-opens the trust surface. Apply a standing acceptance gate to every wave: no change ships if it makes a displayed number wrong, and any data-mutating change is flagged + revertable.

P1 · Connective tissue the flywheel — highest-leverage product work

The thesis: well-built tools that don't talk to each other. The data is already there — it just isn't wired. (See diagram, §04.)

04

The flywheel

Target architecture for connection. A finance product wins on the loop record → reconcile → project. Today every arrow below is missing; the dashed box (liabilities) doesn't exist yet.

Read it as: Budget supplies the cash-flow facts (savings, expenses); Holdings + Assets supply value and a derived risk band; Overview is the hub that nets it all into true net worth and deep-links out; Planning finally sees the whole portfolio; Insights reads the connected whole.

Lead theme fixed by the owner: trust first. Sliced by reversibility, not just theme — within every wave, data / egress changes are flagged + individually revertable; pure-UI changes ship freely. The obvious entry point is W1a.

flagged · gated

06

Release rules

From the reliability review. This is a client-side, single-user, on-device app — the reliability surface is the user's local data and the privacy guarantee, not a server fleet.

1
Each data-mutating item rides its own featureFlags.ts flag with a documented on-device revert: flip flag + redeploy the static bundle; the user restores a pre-change backup for migrated data.
2
IndexedDB migrations (W3 liabilities) never share a release with cosmetic changes. Ship gate = backup + round-trip test.
3
Centralize any derived value (e.g. assetClass→riskBand) in one unit-tested module — it fans out to Planning / Overview / insights, so a wrong mapping is silently wrong everywhere at once.
07

Review lenses

Two fresh-context reviewers pressure-tested the prioritization before it was written down.

4 Shapes

Nature
A trust-bearing instrument — one wrong reading poisons every correct one beside it; trust erodes continuously, so it's an invariant, not a wave.
Domain
Load-bearing nouns are net worth / cash flow / position / plan; record → reconcile → project. With no backend, the user is the reconciliation authority — and has no way to confirm a total.
Theory
A fold over an event log into derived views; "derive don't store" (risk band) is the clean move; trend/milestones need a history series built before the views that read it.
Implementation
Derive-with-override is the right smallest spike; the consent layer is medium-large and shouldn't share a wave with a one-line fix; FX is on the trust critical path.
Tensions
trust-as-wave vs trust-as-invariant · consent-valve-before-its-water · tissue and the Planning trust-fix are the same work.

Reliability tenets

Tenet 2 · Critical path simple
Isolate data-mutating changes (consent, snapshot seed, migration) from cosmetic ones — never share a release boundary.
Tenet 3 · Blast radius
The derived risk band fans out to many surfaces — centralize + unit-test the mapping so a bad band can't propagate unaudited.
Tenet 6 · Staggered rollout + rollback
Per-item flags; consent defaults OFF and stays OFF on upgrade; on-device rollback is flag-flip + user backup restore; the migration is gated by a round-trip test.
Not applicable
Redundancy / failover, dynamic capacity, SLA/SLOs, org-wide ownership — no server fleet, no traffic, single owner.
08

Pre-mortem

For the W1 the roadmap recommends.

Most likely failure

W1b's baseline snapshot is built as a naive "add snapshot on commit" → a same-day re-import overwrites the YYYY-MM-DD row, corrupting the series the trend charts later read. And/or the consent layer is added while the existing FX-at-import egress keeps firing — so the app still calls Frankfurter before any opt-in.

Rollback

Per-item flags (FEATURE_CONSENT, FEATURE_BASELINE_SNAPSHOT); flip off + redeploy the static bundle. W1 adds no schema, so nothing to reverse. The irreversible W3 liabilities migration is gated separately; user-level revert = restore a pre-migration backup.

Detection + responder

No runtime telemetry is allowed, so detection is build-time: a Vitest assertion that no network call fires while consent is OFF; a unit test that a same-day re-import leaves exactly one snapshot row; the existing Playwright evidence pass on the seeded fixture. Responder = the single owner.
