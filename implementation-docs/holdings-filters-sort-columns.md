## Research summary

- `CanonicalHolding` (`src/storage/holdings.ts:9-21`) stores `quantity`, `avgBuyPrice`, optional FX fields — **no current price**. DB is at version 2 (`:29`); optional scalar fields need no bump.
- Broker exports carry a current price, verified against fixtures: **Groww** header row 11 has `Closing price`; **Vested** `Holdings` sheet has `Current Price (USD)`.
- `mapHeaderColumns` (`src/parsers/xlsx-utils.ts:25-32`) returns `Map<colName, colIndex>` — read an optional column via `.get('Closing price')` guarded by an `undefined` check. **`cellNumber` (`xlsx-utils.ts:13-23`) returns `0` for an absent/blank/garbage cell** — so the parser must distinguish "column absent" from "value 0" by the column name's presence in the map, never by the cell value.
- `stampHolding` (`src/lib/refreshFx.ts:12-25`) computes `avgBuyPriceBase = avgBuyPrice * effectiveRate(...)`; `currentPriceBase = currentPrice * rate` is the identical transform at the same call site. `StampedHolding` (`:6-10`) makes `avgBuyPriceBase` required — the new `currentPriceBase` must be **optional** (`currentPrice` itself is optional, and import FX can fail: `PreviewStep.tsx:42-45` passes rows through unstamped when `rate === null`).
- `stampHolding` is the single chokepoint for all three stamping callers — `refreshFx` (`:45`), `applyManualRate` (`:63`), import `PreviewStep` (`:42-44`).
- Current UI: `HoldingsTable.tsx:38` sorts by name (one hard-coded line); desktop table `:51-117`, mobile cards `:120-156` (no header row); `baseCostLabel` `:32-35` is the `—`-fallback precedent. `HoldingsRoute.tsx:14-31` empty state, `:48-51` `RefreshBanner` for FX-unstamped rows.
- `formatMoney` / `formatQuantity` exist (`src/lib/format.ts:14-24`); **no percent formatter** — add one.
- Full detail + citations: `notes/holdings-filters-sort-columns/research.md`.

## Approaches considered

### Approach 1: Extend HoldingsTable in place
Sort/filter `useState` and all derived math live inside `HoldingsTable.tsx`. Fewer files, but the partial-value math (undefined price, undefined FX, zero-invested) is only reachable through a rendered component — untestable without rendering, easy to regress. Medium complexity. Ruled out for testability.

### Approach 2: Pure `holdingsView.ts` module + thin component (recommended)
A new pure module `src/lib/holdingsView.ts` owns per-row derivation (`DerivedRow` = holding + `costBase`, `currentValueBase`, `profitAbsBase`, `profitPct` — each explicitly `undefined` where price/FX is missing), the per-column sort comparators (asc/desc, `undefined` sorts to the bottom both directions), and the filter predicates (market, text search). `HoldingsTable` becomes presentational, fed `DerivedRow[]` + state via props. Sort/filter state is `useState` in `HoldingsRoute`. Matches the codebase's established pure-logic-module + thin-component convention (`refreshFx.ts`, `diff.ts`, both unit-tested). One extra file + its test. **Recommended.**

### Approach 3: Generic DataTable abstraction
Ruled out — exactly one table exists in the app; a config-driven generic table for a single consumer is speculative abstraction the CLAUDE.md "build only what Phase 1 needs" rule forbids.

Full detail: `notes/holdings-filters-sort-columns/approaches.md`.

## Confirmed design decisions (grill loop)

1. **Price source**: import-time snapshot from the broker export (`Closing price` / `Current Price (USD)`). Live API tracked as issue #10.
2. **Columns** (9, in order): Name (+symbol, asset-class badge), Mkt (IN/US badge), Qty, Avg Price Bought (native ccy), Current Value/unit (native ccy — label to match broker term "current price"), Total Invested (base ccy), Current Total Value (base ccy), Profit (abs + %), Broker. № index dropped; Class folded to a badge under the name.
3. **Totals currency**: Total Invested / Current Total Value / Profit-abs in the settings base currency (needs `currentPriceBase`). Per-unit prices stay native. Profit % is currency-neutral.
4. **Sort**: every column sortable asc/desc; default = Current Total Value desc. Desktop = click column header to toggle; mobile = "Sort by" dropdown + asc/desc direction toggle.
5. **Filters**: by market (IN/US) and by symbol/name text search.
6. **Staleness**: page caption shows the newest import date; rows whose import is older than the newest get a subtle "stale" marker.

## 4 Shapes (from develop-perspective)

- **Nature**: snapshot vs. live is photograph vs. live feed — a photo carries a timestamp; the stale-row marker *is* that timestamp, flowing with nature rather than pretending the number is live. The table is sedimentary — each import a dated layer.
- **Domain**: personal-investing, not payments; the holding is a *derived view*, not a state machine. The table is the post-import analytics end of import → reconcile → view. Vocabulary is standard (cost basis, P&L, base currency) — label the current-price column to match the broker's own term.
- **Theory**: `holdingsView.ts` is a pure projection (`map`); sort = total order, filters = conjoined predicates. The sharp point — derived values are **partial functions** (`profitPct` undefined at invested = 0, `currentValueBase` undefined when price/FX missing); model with `undefined`, never a sentinel `0`/`NaN`; sorting a partial column needs `undefined` ordered to the bottom both directions.
- **Implementation**: existing code hands you the shape — `stampHolding` is a one-line per-field transform, `baseCostLabel` is the `—`-fallback render. Friction the diagram hides: `cellNumber` returns `0` for an absent column (gate on the column-name map instead), and `StampedHolding` makes `avgBuyPriceBase` required (`currentPriceBase` must be optional).
- **Tensions**: (a) Nature (a snapshot is honestly fixed) vs. Domain (a portfolio view wants to feel live) — the stale marker resolves it at the UI but is a band-aid over the gap issue #10 must close. (b) Theory (model partiality with `undefined`) vs. Implementation (the codebase's `cellNumber` returns the sentinel `0`) — the plan must actively stop `0` from masquerading as a real price, since a `0` price renders a false −100% loss.

Full output: `notes/holdings-filters-sort-columns/perspective.md`.

## Picked Reliability Tenets (from reliability-tenets)

- **Tenet 2 — Critical path simple**: the import → stamp → persist pipeline is the only path that can corrupt durable data. Keep `currentPrice` / `currentPriceBase` optional, **no DB version bump**, no migration. Making `currentPriceBase` required on `StampedHolding` would break the FX-failed passthrough (`PreviewStep.tsx:42-45`) — keep it `?`-optional everywhere.
- **Tenet 3 — Blast radius**: a malformed export must not blank the whole table. `holdingsView.ts` per-row derivation is the bulkhead — a non-finite `currentPrice`/`avgBuyPriceBase` yields one `—` cell, never a thrown render.
- **Tenet 4 — Anomaly detection**: no telemetry (privacy-first), so the test suite *is* the detector — `holdingsView.test.ts` must assert the partial-value contract or regressions ship silently.
- **Tenet 6 — Rollback**: a static GitHub Pages bundle cannot stagger (deploy = 100%). Compensation: the change is additive/reversible — rollback is `git revert` + redeploy, no data migration to undo (no version bump). **Tension**: no safe post-deploy ramp ⇒ correctness must be proven pre-deploy by tests + Playwright verification.

Full output: `notes/holdings-filters-sort-columns/tenets.md`.

## Pre-mortem

- **Most likely failure**: a real broker export with a missing/renamed/garbage current-price column makes `cellNumber` return `0`, which propagates as a real price → the whole table shows Current Total Value ≈ 0 and Profit ≈ −100%. A confident, plausible, alarming wrong number with no signal it's a parsing artefact. Prevention: the parser reads the current price **only when its column name is present in `mapHeaderColumns`**; absent column → `currentPrice = undefined` → `—` cells.
- **Rollback**: `git revert` the feature commit(s) + redeploy (~1 min, all-or-nothing). No DB version bump ⇒ no migration to undo; old code reads named fields by spread and ignores the extra `currentPrice`/`currentPriceBase`, so records imported under new code still load on the reverted build. Pre-merge check: confirm the old build renders a holding record containing `currentPrice` without error.
- **Detection + responder**: no telemetry — detection is pre-deploy. (1) `holdingsView.test.ts` asserts the partial-value contract; (2) `groww.test.ts`/`vested.test.ts` gain a fixture with the current-price column *absent*, asserting `currentPrice === undefined` (not `0`); (3) Playwright verification per `.claude/rules/frontend-design.md` before the draft PR is marked ready. Continue/roll-back gate: rendered Current Total Value figures must match the broker file's own totals (Groww `Closing value`, Vested `Current Value (USD)` give a free cross-check). Responder: implementing engineer during `/implement-lite` + PR review.

Full detail: `notes/holdings-filters-sort-columns/premortem.md`.

## Recommendation

Take **Approach 2** — a pure `src/lib/holdingsView.ts` projection module (per-row derivation + sort comparators + filter predicates) behind a thin presentational `HoldingsTable`, with sort/filter state in `HoldingsRoute`. The main tradeoff is one extra module + test versus Approach 1's inline math — worth it because the real bugs live in the partial-value cases (undefined price, undefined FX, zero invested), and only a pure module makes them testable without rendering. The non-negotiable discipline across the whole change: a missing column becomes `undefined`, never `0` — a sentinel `0` price renders a false total loss. The user can still redirect on the current-price column label and on whether the stale-row marker is a sufficient honesty signal versus pulling issue #10 forward.

### Suggested implementation order (for `/implement-lite`)

1. Schema: add `currentPrice?` / `currentPriceBase?` to `CanonicalHolding` (`storage/holdings.ts`). No version bump.
2. Stamping: `stampHolding` also computes `currentPriceBase` when `currentPrice` is defined; `currentPriceBase?` optional on `StampedHolding`.
3. Parsers: Groww reads `Closing price`, Vested reads `Current Price (USD)` — optional, gated on column-name presence. Extend `groww.test.ts` / `vested.test.ts`, incl. a column-absent case.
4. `src/lib/holdingsView.ts` + `holdingsView.test.ts`: `DerivedRow` type, derivation with explicit `undefined`, sort comparators (undefined-to-bottom), filter predicates. Add a percent formatter to `format.ts`.
5. `HoldingsTable.tsx` rewrite: 9 columns, desktop click-header sort, mobile dropdown sort, stale-row marker, filtered-empty state.
6. `HoldingsRoute.tsx`: filter/sort `useState`, filter controls, page caption with newest import date.
7. Playwright verification per `.claude/rules/frontend-design.md` before the draft PR is ready.
