# Plan: CSV/XLSX import — Vested + Groww → IndexedDB → list view

> Generated by `/brainstorm-lite` on 2026-05-14. Working notes at `notes/csv-import-vested-groww/`. Sample broker exports at `notes/csv-import-vested-groww/samples/`.

## Frame

- **Kind**: feature (first vertical slice of Phase 1)
- **One-line summary**: User lands on app → if IndexedDB has no holdings, route to an **Import wizard** (pick source → platform-specific download instructions → upload `.xlsx` → preview diff → resolve missing rows → commit); otherwise route to the **Homepage list view** showing canonical holdings (Vested + Groww unified, with `source` visible as a first-class column).
- **Files/modules likely touched**:
  - `src/App.tsx` (rewrite — router setup, empty-storage redirect)
  - `src/routes/home/{HomeRoute,HoldingsTable}.tsx` (new)
  - `src/routes/import/{ImportRoute,SourcePicker,Instructions,UploadStep,PreviewStep,CommitStep}.tsx` (new)
  - `src/parsers/{types,groww,vested,diff}.ts` (new)
  - `src/storage/holdings.ts` (new — `idb` wrapper, single `holdings` object store keyed by compound `[source, sourceSymbol]`, `upgrade` hook scaffold)
  - `package.json` (+ `idb`, `xlsx`, `react-router-dom`)
- **External surface affected**: **none**. Edge-only, no server, no public API. Only on-device change is the new IndexedDB database.
- **Out of scope** (deferred — do not design speculatively):
  - Live prices / current value / unrealised P&L (later: price-data slice)
  - USD↔INR FX conversion (later: FX slice)
  - Analytics views — allocation, P&L over time, performance (later: analytics slice, likely triggers SQLite-WASM re-evaluation)
  - ISIN→ticker resolution (Groww) and ticker→exchange resolution (Vested) — list shows what the source gave us
  - Manual add-a-holding form (later: manual-entry slice)
  - Edit / delete an individual holding from the list view (delete-via-re-import is the only delete path in v1)
  - Transaction-level history / snapshot history (later: analytics-history slice)
  - Restore-from-backup action — the backup *download* ships in v1; the *restore* UX is the settings slice

## Research summary

Full citations in `notes/csv-import-vested-groww/research.md`. Highlights:

- The codebase is a bare Vite + React 19 + TS + Tailwind v4 scaffold (4 source files). Zero existing conventions for routing, storage, parsing, or testing — this slice **establishes the precedent** for all of them (`src/App.tsx:1-23`, `package.json:11-22`, `vite.config.ts:6`).
- `vite.config.ts:6` sets `base: '/investment-dashboard/'` for GitHub Pages — any router added must take the same string as `basename`.
- `.claude/rules/frontend-design.md:23-57` requires Playwright MCP verification before any UI-touching draft PR is marked ready-for-review. This slice's `/implement-lite` follow-on must capture screenshots of: empty-state, source-picker, instructions, upload, preview (with and without missing rows), commit success, list view (single source, both sources).
- **Groww export** (`Stocks Holdings Statement May 13 2026.xlsx`, 6 KB, ~30 data rows): banded XLSX, data header at **row 11**, columns `Stock Name | ISIN | Quantity | Average buy price | Buy value | Closing price | Closing value | Unrealised P&L`. ISIN-keyed (no ticker). Includes MFs/ETFs/InvITs alongside equities. Contains "NA" ghost rows (zero qty, no name) to skip.
- **Vested export** (`Vested Holdings Dashboard.xlsx`, 22 KB, ~15 data rows): clean XLSX, header at **row 1**, columns `Name | Ticker | Total Shares Held | Current Price (USD) | Current Value (USD) | Average Cost (USD) | Total Amount Invested (USD) | Investment Returns (USD) | Investment Returns (%) | Daily Change (USD) | Daily Change (%)`. Ticker-keyed. Fractional shares supported (e.g., 2.7, 0.6, 2.725). Mix of equities and ETFs (`VOO`, `SOXX`, `ROBT`, `KTEC`).
- **Libraries picked**: [`exceljs`](https://github.com/exceljs/exceljs) — MIT, ~800 KB, actively maintained, parses XLSX via `workbook.xlsx.load(buffer)` + `worksheet.eachRow`. *(Initially planned: SheetJS `xlsx`. Switched at implementation time after `npm audit` flagged two unpatched advisories in the npm-published xlsx package — Prototype Pollution GHSA-4r6h-8v6p-xvw6 + ReDoS GHSA-5pgg-2g8v-p4x9. User-ratified the switch to exceljs over installing-from-SheetJS-CDN-tarball.)* [`idb`](https://github.com/jakearchibald/idb) — MIT, ~1 KB gzip, promise wrapper over IndexedDB. [`react-router-dom`](https://reactrouter.com) v7 in SPA mode. [`vitest`](https://vitest.dev) — MIT, Vite-native test runner; bootstrapped in this slice since the scaffold had no tests.
- **Storage decision**: IndexedDB now. **SQLite-WASM deferred** to the analytics slice with two constraints flagged: (a) GitHub Pages can't set COOP/COEP response headers — OPFS-VFS variant needs a service-worker shim like `coi-serviceworker` or fall back to non-OPFS sql.js; (b) ~600 KB–1 MB WASM bundle — must be lazy-loaded behind the analytics route.

## Approaches considered

Full text in `notes/csv-import-vested-groww/approaches.md`.

### Approach A: Router + wizard, `useReducer` state, `idb` + SheetJS  *(RECOMMENDED)*

- `react-router-dom` v7 SPA with two routes: `/` (home) and `/import` (wizard). Root-level guard redirects `/ → /import` when `holdings.length === 0`.
- Wizard as a single `<ImportWizard />` driven by `useReducer` on `{ step, source, file, parsed, diff, decisions }`.
- Parsers as pure functions: `parseGroww(file): Promise<ParseResult>`, `parseVested(file): Promise<ParseResult>`, both returning `{ rows: CanonicalHolding[], skipped: number }`.
- Diff as pure function: `diff(existingForSource, incoming, source) → { inserts, updates, missing }` — note the source-scoped signature for per-source containment (Tenet 3).
- Storage: thin `src/storage/holdings.ts` with `getAll()`, `getForSource(source)`, `commitImport({ inserts, updates, deletes })` in one `idb` transaction, `exportSnapshot(): Blob` for the backup-download button.
- Schema versioning hook in `idb`'s `upgrade(db, oldVersion)` callback wired from v1 (no-op for v1, scaffolding for future migrations with backup-snapshot-before-migrate).
- **Complexity: medium.** Driver is the preview step's UX (per-row keep/delete, bulk actions, value-sanity row).

### Approach B: No router, view-state in `App.tsx`  *(rejected)*

Saves one dependency and a few KB, but pays back immediately the next feature (Settings, holding detail, link-shareable filters all need URL state). Deferred complexity, not removed. Rejection logic in `notes/.../approaches.md`.

### Approach C: Web-worker parsing + XState wizard  *(rejected)*

Premature scaling. Real Groww file is 6 KB / sub-millisecond parse; XState is a 50 KB dep for a linear 5-step wizard with one conditional skip. `useReducer` is the right tool here.

## 4 Shapes (from develop-perspective)

Full analysis in `notes/csv-import-vested-groww/perspective.md`.

- **Nature**: a watershed — heterogeneous tributaries (Vested, Groww, future Robinhood/Zerodha) drain into one canonical reservoir through a preview-and-consent gate. Concern: we discard the sedimentary-layer pattern (per-upload snapshots) — unrecoverable later if the analytics slice wants "value as of date X".
- **Domain**: vocabulary is Holding / Cost Basis / Source. The slice models *positions* (snapshot view) deliberately, not *transactions* (event ledger). Source as first-class field matches the user's mental model ("my Groww holdings + my Vested holdings"). Lives entirely in pre-portfolio (data ingest); doesn't bleed into compute (live prices) or post-portfolio (analytics).
- **Theory**: canonical-holdings is a **G-Map (grow-only map) with LWW values keyed by `(source, sourceSymbol)`** — a well-studied CRDT. The "missing-from-upload" branch sidesteps LWW's classic remove problem by making removal explicit user consent. Wizard is a linear DFA with one conditional skip → `useReducer`, not XState.
- **Implementation**: empirically verified the files via Python during research (6 KB / 22 KB → trivial). Real data exposed two things docs didn't: NA-ghost rows and asset-class bleed in Groww's "stocks" export. The slice **sets precedent** for the next 5 features (parser file layout, storage interface, route structure, schema-migration hook) — its choices propagate.

**Tensions**:
- Theory says snapshot history is a cheap CRDT extension; domain says current state is the mental model; implementation says ship small. We side with domain + implementation; analytics slice pays interest.
- Domain says cost basis is sacred; merge semantics overwrite `avgBuyPrice` on every re-import. Trusting the broker is acceptable — surface a one-line warning in the UI.
- The snapshot-history discard is the single most consequential design loss — recorded so the analytics slice walks in eyes-open.

## Picked Reliability Tenets (from reliability-tenets)

Full text in `notes/csv-import-vested-groww/tenets.md`.

- **Tenet 2 (critical path = simple)**: `commitImport` runs inside one `idb` transaction — atomic, no half-writes. v1 schema is minimal and is a long-term promise; resist additions.
- **Tenet 3 (blast radius)**: parsers validate at the gate with named-column assertions (return typed `ParseError`, never silent zero-row); per-source containment in the diff signature; **"Download backup (.json)" button on the preview step** — single highest-leverage reliability investment in v1.
- **Tenet 4-adapted (detection at the gate)**: preview-step counters (`inserts / updates / missing / NA-skipped`) + an **"extreme values" sanity row** are the alert system; `ParseError` messages must include offending row text and parser version so the user can self-diagnose.
- **Tenet 6 (rollback)**: code rollback via `git revert HEAD && push`; data rollback via the backup .json file (restore action deferred to settings slice); **`upgrade(db, oldVersion)` hook wired from v1 as scaffolding** so future migrations inherit backup-snapshot-before-migrate.

## Pre-mortem

Full text in `notes/csv-import-vested-groww/premortem.md`.

- **Most likely failure**: Groww or Vested silently changes their export shape (column inserted, header renamed, units shifted from rupees to paise), OR the user uploads the wrong export type. If parsed positionally → silent corruption; if parsed by named header with explicit assertions → loud rejection. **The named-column-with-assertions design is the difference between unrecoverable corruption and "rejected upload."**
- **Rollback**: code = `git revert HEAD && git push`, redeploys in ~2 min. Data = restore from the backup .json file (manual `idb` insertion via DevTools is fine for a single user until the settings-slice restore action ships). Without the backup button in v1, data rollback is impossible — which is why it's scoped in.
- **Detection + responder**: at parse time, typed `ParseError` rendered as a red banner with the offending row text — user is the responder, files an issue. At preview time, the counters + extreme-values row are the alert — user cancels and files an issue. Recovery: parser patched in a follow-up commit, regression test added using a fixture mimicking the bad file.

## Recommendation

Build **Approach A** (router + wizard + `useReducer` + `idb` + SheetJS, parsers per source). The recommended scope for v1 includes the "Download backup (.json)" button on the preview step — small code cost, qualitatively better blast-radius story. The main tradeoff redirected here: we sacrifice per-upload snapshot history (a cheap CRDT extension) to keep v1 minimal — this is the single design call most likely to bite later, and it's flagged for the analytics slice.

One open call worth ratifying or overriding: **"Download backup (.json)" button on the preview step — in v1 (recommended) or pushed to a follow-on settings/backup slice?** Default in this plan is "in v1." Say so if you want it deferred.
