# Fix all 8 "Now" items from the PM review roadmap

> Implemented via `/brainstorm` → `/develop` on 2026-09-06.

## What

Nine commits on `fix/pm-review-now-fixes` (branched from `origin/main`) fixing every item in the "Now" bucket of a four-audit PM review of investment-dashboard — the fixes judged to block trusting the tool with real money data. No schema version bump, no external API surface change; every change is either a TypeScript-level field addition on an in-memory return type or a pure-function/UI fix.

Touches: the import pipeline (`src/parsers/diff.ts`, both parsers, `PreviewStep.tsx`, `CommitStep.tsx`, `wizardState.ts`), storage/analytics (`src/lib/netWorth.ts`, `src/lib/investments.ts`), font delivery (`index.html`, `src/index.css`, new `src/assets/fonts/`), app boot (`src/main.tsx`), one UI-bug cluster (`src/routes/PortfolioRoute.tsx`), and two docs (`README.md`, `productContext/architecture.md`).

## Why

A prior PM review (four independent audits — functional, non-functional, UI/UX, competitive — each citing file:line or command output) found the app's own docs claimed "Phase 1 — first vertical slice shipped... FX and analytics land in later slices" while FX, analytics, budget, and planning were already shipped and on by default. Behind that stale framing sat eight real, live bugs:

1. **`index.html` loaded three fonts from Google's CDN** on every page load, before first paint — the app's only non-Frankfurter network egress, violating the edge-only hard constraint in `CLAUDE.md` and breaking fully-offline use.
2. **`diffHoldings` never checked incoming rows against each other.** Two rows sharing a `sourceSymbol` in one import file both reached `inserts`; the second `store.add()` threw a raw IndexedDB `ConstraintError` and aborted the whole commit — *after* the preview screen had already shown both as safe. On re-import, the same case silently last-write-won with zero signal.
3. **Garbage cost-basis cells silently imported as `avgBuyPrice: 0`,** understating invested capital with no error, because the parser's ghost-row check only tested `name`/`quantity`.
4. **A failed live FX fetch during import commit produced no user-visible signal** when a stale rate was already on record — only a `console.warn`, and only in the one case where no fallback rate existed at all.
5. **Zero calls to `navigator.storage.persist()`** anywhere — no defense against Safari ITP's 7-day wipe or storage-pressure eviction beyond a user manually exporting a backup.
6. **`netWorthTotals` had no guard against non-finite values,** unlike its sibling fold in `lib/investments.ts` — a NaN/Infinity row could poison a total without being counted as excluded.
7. **README and `productContext/architecture.md` were badly stale** — wrong DB version (claimed 1, actual 5), wrong store count (claimed 1, actual 6), routes and components that no longer exist (`/analytics`, `/holdings`, `AnalyticsRoute.tsx`, `HoldingsRoute.tsx`), and a false claim that restore-from-backup was still deferred (it shipped in PR #31).
8. **Two live UI bugs**: the Other-assets Edit button always opened a blank "Add asset" modal instead of editing, and the risk-row's "no position >10%" copy asserted a conclusion the data couldn't support when nothing was priced at all.

**Approach.** Only one approach was considered — every fix extends an existing in-codebase pattern (the parser's own `cellNumberOrUndefined` helper, the existing `editing`/`setEditing` edit-modal pattern, the existing `finite()` guard in `investments.ts`) rather than inventing new architecture, so there was no competing design to weigh. A plan-review pass (two independent fresh-context reviews — a 4-Shapes/Nature-Domain-Theory-Implementation lens and a reliability-tenets filter) converged on the same core finding from two angles: bundling all 8 items into one PR contradicted the plan's own "independent, surgical fixes" framing, since a regression in one item would force reverting all eight. **Resolved structurally**, not by re-opening the already-decided one-PR/one-branch choice: one commit per item, so `git revert <sha>` undoes a single item without touching the others, plus an explicit build order (docs written last, checked against the real final diff rather than the plan's description of it). The same review sharpened three items concretely: item 2 now returns the *discarded* duplicate row's full data instead of silently dropping it (a future per-row picker can consume it directly); item 4's FX-warning decision was extracted into a pure, directly-unit-tested function instead of relying on TypeScript's required-field check alone; item 6's `finite()` guard was consolidated into `netWorth.ts` (the correct direction in the existing import graph) instead of staying duplicated. Every finding from both review passes was folded in — none deferred.

**Pre-mortem.** Most likely failure: item 2's keep-last dedup silently collapses a *legitimate* two-lot position (the same broker splitting one holding across two rows) into one row, losing the discarded lot's quantity/cost-basis — better than the prior crash or silent last-write-win, and visible via the new "Duplicates" count, but not a *correct* outcome for that specific input shape. This is the deliberate, user-approved "minimal now, full picker later" tradeoff, not a defect. Rollback: one commit per item → `git revert <sha>` → automatic redeploy via the existing `deploy.yml` GitHub Actions workflow; no `DB_VERSION` bump in any of the 8 items, so no migration to revert. Detection: no telemetry (by design, per the app's privacy-first constraint) — the pre-merge gate (test suite, typecheck, build) plus a new cross-item integration test are the only safety net for a single-user project with no monitoring.

## How

Implemented and committed one item at a time, each following the plan's bugfix rule (failing test first, watch it fail, fix, watch it pass) where a meaningful test seam existed:

- **`fix(netWorth)`** — added the shared `finite()` guard (moved from `lib/investments.ts`, which now imports it back) to `netWorthTotals`; two new tests cover a NaN `currentValueBase` and an Infinity `investedBase`.
- **`fix(parsers)`** — swapped `cellNumber` → `cellNumberOrUndefined` for the required `quantity`/`avgBuyPrice` columns in both parsers; an unparseable required cell now skips the row (folds into the existing `skipped` counter, per an explicit product decision *not* to add a separate UI counter for this). New tests for both parsers.
- **`fix(import)` (dedup)** — `diffHoldings` now dedupes `incoming` against itself by `sourceSymbol` before building inserts/updates, keeping the last occurrence and returning the discarded rows as `duplicates: DuplicateRow[]` on `DiffResult`. `PreviewStep` renders the count as a fifth Stat tile. Per an explicit product decision, the full per-row Combine/Keep-one picker is deferred (captured for that future work: "combine" = quantity-weighted-average cost basis across the duplicate lots) — this fix only stops the crash and the silent overwrite, it doesn't add a decision UI.
- **`fix(import)` (FX warning)** — extracted `deriveFxWarning(liveFxFailure, fallbackRate, fallbackFetchedAt)` as a pure function in `lib/refreshFx.ts` with three unit tests (live success, live failure with a stale rate on record, live failure with none at all). Threaded through `WizardState`'s `commit-ok` action (verified via `grep -rn "commit-ok" src/`: exactly one dispatch site, one reducer case) to an inline amber note on `CommitStep`'s Done screen, reusing the existing warning-tone treatment from `commitError`/`RefreshBanner`.
- **`fix(storage)`** — one fire-and-forget `navigator.storage.persist()` call in `main.tsx`, feature-detected for Vitest's jsdom environment. No dedicated test — this file has no existing test harness and the call has no application-level branching logic to test.
- **`fix(fonts)`** — downloaded the same three font families/weights the app was already loading from Google Fonts (verified via direct negotiation with a realistic `Accept` header — Bricolage Grotesque is a genuine variable file across weight 600-800; Instrument Sans and JetBrains Mono needed discrete per-weight static files, since an initial fetch attempt without a proper `Accept` header caused Google to silently collapse all four/three requested weights onto one mislabeled file, which was caught and corrected before committing). Self-hosted under `src/assets/fonts/`, `@font-face` rules added to `src/index.css`, the three `<link>` lines removed from `index.html`. Verified zero remaining `fonts.googleapis.com`/`fonts.gstatic.com` references anywhere in source or the built `dist/` output.
- **`fix(portfolio)`** — added `editingAsset` state mirroring the existing `editing` pattern used correctly for holdings, plus a dedicated edit-mode `AssetForm` instance (the component already fully supported `mode="edit"`; it needed zero changes). Fixed the risk-row copy by using the sibling `c.top5Pct` field — `undefined` in and only in the zero-priced-holdings case — to tell "nothing priced yet" apart from "measured, genuinely below the 10% threshold." No test added: this repo has zero component-test infrastructure anywhere (confirmed by search, not assumed), and building that harness was out of scope for this change.
- **`docs(architecture)`** — written last, after the seven code fixes above landed and the full verification gate passed, checked against the actual current code (`DB_VERSION`, store names, real route list, real component tree) rather than against the plan's description of it. Corrected README's phase-status framing and stack claims; corrected `architecture.md`'s component map, routing table, storage table, FX/import-pipeline sections, and its `arch-gaps` section's false "restore UX deferred" claim.

**Review loop.** `/deep-review` ran twice per the plan's autonomous review-and-fix loop. First pass: **Block: 1** — the cross-item integration test (added alongside the dedup fix to exercise items 2 and 3 together, per the reliability-tenets review's own recommendation) lived inside item 2's commit but asserted item 3's behavior, so `git revert`-ing item 3 alone would leave a failing test in the tree with no obvious cause — contradicting the plan's per-item-revert claim. Also one Nit (dead `cellNumber()` function, orphaned once both parsers switched to `cellNumberOrUndefined`). Fixed in commit `0230b0e`: moved the test to its own file (`diff.integration.test.ts`) with a doc comment naming the two-fix dependency explicitly, and deleted the dead function. Second pass: **Block: 0, Request changes: 0, Follow-up: 0, Nit: 0** — clean.

**Verification**: `npm run typecheck` — clean. `npm run build` — succeeds; self-hosted fonts appear as hashed files in `dist/assets/`, zero remaining Google Fonts references confirmed by grep across source and build output. `npm run test:run` — 287/287 passing across 22 files (up from a 274-test baseline; +13 new tests across items 2/3/4/6 plus the cross-item integration test). No formatter exists in this repo (no prettier/eslint config, no lint/format script) — that step was skipped, not silently omitted.

**Not yet done, and explicitly out of scope for `/develop`**: Playwright golden-path + edge-case verification for the four user-visible items (1 — fonts render with no FOUT/layout shift; 2 — the new Duplicates stat tile on a file with a repeated row; 4 — the fxWarning banner on a forced live-fetch failure; 8 — the asset-edit modal opening pre-filled, and the corrected risk-row copy), per `.claude/rules/frontend-design.md`'s gate. That capture-and-post procedure belongs to `/do`'s "evidence" step against a pushed, open PR — the engineer runs it (or invokes `/do`) before marking this PR ready-for-review.
